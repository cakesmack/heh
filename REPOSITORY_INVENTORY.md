## Scope and method

The complete master context (`events_hub_context.md`, sections 1–14) was read before repository analysis. `.agents/AGENTS.md` and `AGENT_RULES.md` were also read. The authoritative constraints are Next.js Pages Router, FastAPI, PostgreSQL/SQLModel, Alembic model migrations, isolated typed ingestion, required HTML sanitization, protected branding/navigation, canonical SEO routes, a date-range map with its seven-day default, shared EditVenueModal, and the documented ticketing/moderation safeguards. This inventory does not authorize changing those rules or any application file.

Enumerated **577 significant files**, including **496 tracked** and **81 ignored local files**, across **107 first-party directories** (including empty directories). Installed dependencies, Git internals, compiled caches and build output were enumerated/count-accounted separately; third-party package implementation files are not individually audited. The appendix lists every significant first-party file, not just examples. Generated Python bytecode is separately listed because some source files are absent. The report itself is an audit output and is excluded from baseline counts.

Read manifests, startup scripts, router registration, migration runners, schema/model exports, tests, script purposes, and documentation. Used static Python import parsing and TypeScript relative/@ alias, re-export and literal dynamic-import resolution. Traversed from every Pages Router file, middleware, FastAPI main, Alembic environment and deployment migration runner; accounted for Python package __init__ execution. Also searched literal filenames, template loaders, public URLs, startup commands and script data paths. Calculated SHA-256 for all 577 significant files to detect exact duplicates and preserve a read-only baseline.

No application import, test suite, build, migration, maintenance command, database query or external API call was executed. Some scripts/tests commit database changes merely when run; executing them was unnecessary for this inventory. No production file was modified, deleted, renamed or moved. The only addition inside the repository is this report; temporary analysis helpers were placed in the containing workspace’s `../tmp/`.

Limitations: static absence is not proof of non-use. External Render settings, scheduled tasks, historical deployment revisions, installed PWA clients, email links, database-stored asset URLs, Git history and production traffic were not inspected. Git status initially showed a clean tracked working tree; a process-local safe.directory option enabled read-only Git access without changing Git configuration. Sandbox denial on two pytest caches was resolved through an approved read-only listing. Their contents were counted, not executed. No directory enumeration errors remain unresolved.

## Important dependency findings

### Migration and startup files are not cleanup targets

`backend/Dockerfile` → `start.sh` → `alembic upgrade head` → `scripts/run_migrations.py` → Uvicorn. `release.sh` also runs Alembic, the SQL runner and slot-pricing seeding. FastAPI lifespan → `core/database.py:run_migrations` → the same SQL runner, then `core/inline_migrations.py`. The SQL runner glob-loads every `backend/migrations/*.sql`, records filenames in schema_migrations, and invokes slot pricing, preferences backfill and uncategorized venue migration. Lack of a literal filename import does not make a SQL migration unused. Even `006_purge_test_bookings.sql` is startup-discovered and must remain KEEP pending a separate migration audit.

The 17 Alembic source revisions form one connected chain from `2b4255d70229` to `f6a7b8c90123`; parent/head analysis was static, not a query of deployed alembic_version. Schema work overlaps across `007_*.sql` / `e5f6a7b8c901`, `008_*.sql` / `f6a7b8c90123`, and inline migrations. Preserve all paths until deployment history and a consolidation plan exist. Six cached Alembic revisions have no matching source file; their exact paths appear in the cache register. They are historical evidence, not active migration-source replacements.

### Build inputs excluded by ignore rules

`.gitignore` excludes `*.json` with only `frontend/public/manifest.json` re-included. Consequently `frontend/package.json`, `frontend/package-lock.json`, `frontend/tsconfig.json`, and both scripts-node npm files exist locally but are ignored and untracked. The Dockerfile needs npm package/lock files and the frontend alias configuration needs tsconfig.json: all are KEEP. A fresh checkout from this tracked snapshot may lack those required inputs. `.env.example`, docs/ and scrapers/ are also ignored. This is an inventory finding; ignore rules were not changed.

### Compatibility and apparent duplicates that must remain

Every file under frontend/src/pages is a route/framework entry, including create-event, scanner, organizers/scanner, scan/[event_id], admin/collections and admin/curated. `/scanner` redirects to `/organizers/scanner`; `/create-event` uses the shared wizard. Similar functionality does not make these URLs disposable. `VenueEditModal.tsx` is an explicit compatibility re-export of required EditVenueModal; the events CategoryFilterPills wrapper re-exports the categories implementation. Review compatibility callers before considering either wrapper. `EventScheduleSection.tsx` remains imported by wizard/StepTimeline despite neighboring old sections being unmounted.

`backend/app/schemas/payments.py` is imported by schemas/__init__.py, which Python executes on package imports. It is KEEP even without a direct API consumer. Payment models/relationships remain in model registration. `backend/app/services/cloudinary_service.py` remains imported by api/media.py despite Cloudflare migration tools. `email_service.py` and `resend_email.py` also have live callers; similarly named providers are not duplicate deletion targets.

### Tests, empty directories and documentation gaps

`backend/tests/test_private_beta_ticketing_gating.py` now contains tests for standard-user onboarding/tier creation, owner boundaries and single-session/36-hour enforcement: KEEP despite the filename. Backend tests use SQLite fixtures/JSONB compiler shims, while master context mandates PostgreSQL; preserve tests and review their fidelity separately. Pytest is not declared in backend/requirements.txt and no separate test dependency manifest is present. No test results from this inventory are claimed.

`frontend/tests/` is empty; saved promotion Playwright reports are evidence of earlier tests, not current test sources. Caches also mention absent buyer-refund, cron, featured and health test sources. `README.md` describes missing seed/check-in/gamification paths and npm test; backend/frontend README files are identical placeholders. `SYSTEM_MAP.md` documents external scraper files absent from this checkout. These are review/recovery gaps, not permission to reconstruct or remove application code.
